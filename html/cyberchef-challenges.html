Encode, Encrypt, or Hash?

Three operations look the same from the outside: text goes in, scrambled text comes out. They are not the same. One is reversible by anyone, one needs a key, and one can never be undone. Work through five short challenges in CyberChef and feel the difference.

How each challenge works

  2. Paste the input into the Input panel. Find each operation named in the card's recipe line in the Operations list on the left, drag it into the Recipe panel in order, and set any key, IV, or size the card gives.
  3. Read the result in the Output panel, paste it into the check box here, and press Check.

The three families

Encode
Reversible by anyone. No key. Changes how bytes are written, not who can read them. Example: Base64.
Encrypt
Reversible only with the key. The strength lives entirely in the key. Examples: XOR, AES.
Hash
One way. You cannot get the input back. Same input always gives the same digest. Example: SHA-256.

Three pictures to hold onto

Each picture comes with the place where it stops being true, because a picture without its limit quietly teaches a wrong idea.

Pouring water into a bottle
Pour it in, pour it back out. The water changes shape, nothing is hidden, and anyone can empty it.
Where it stops: the water keeps its amount, while encoded output usually grows.
Encode // reversible, no key
Soaking a napkin
Soaked, it is unrecognizable; dried, it comes back. The key is what lets one person dry it and not another.
Where it stops: a real napkin dries on its own, and ciphertext never does. Drying is the key's whole job.
Encrypt // reversible, with a key
Turning milk into curd
Milk sets into curd and never goes back. The same milk and culture give the same curd every time.
Where it stops: more milk makes more curd, but a hash is always the same size.
Hash // one way

Challenges

Going further: cup, mug, tumbler

Hashing has two close relatives. All three take a message and return a short tag, the way three vessels all hold a drink. What separates them is what the tag proves.

Cup = hash
A plain unmarked cup. Anyone can make one and anyone can inspect it, so it catches accidental change and stops nothing deliberate: an attacker who alters the message just makes a fresh cup. Example: SHA-256.
Mug = MAC
A mug with an identical twin in your housemate's cupboard. Making one takes the shared key, so you know it came from a key holder, but neither of you can prove to an outsider which of you made it. Example: HMAC.
Tumbler = signature
A tumbler etched with your initials. The private key that makes the etching is yours alone, and the public key that recognizes it is everyone's, so even a stranger who trusts neither of you can check it. Example: RSA or ECDSA.

Where the vessels mislead: a skilled forger could copy a physical vessel given enough time, while forging these tags without the key is computationally out of reach. Where they hold: all three vessels are the same size whatever goes in, and so are the tags.
